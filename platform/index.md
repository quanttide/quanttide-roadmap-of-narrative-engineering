### 核心发现

- **母题+风格是互补编码**：风格诊断 WHAT，母题给出 HOW。p10 验证组合改法胜在执行质量（具体性+自然度），母题单层胜在瞄准精度（根因对准+母题一致）
- **单场景信号足够**：p05 单篇覆盖率 56-58%，不需要长文本窗口
- **pairwise > 独立评分**：LLM 在相对判断上远优于绝对评分（p10 pairwise 产生显著分化，独立评分全 4,3,3,4,4）
- **两步诊断消除确认偏误**：自由推断→匹配母题库，不预先告知缺失母题列表
- **抽象母题 != 可执行约束**：具象母题（雨 80%、论坛 60%）约束力强，抽象母题（孤独 0%、歌声 0%）是分析性概念非生成性约束

## 下一阶段

### 路线 1：情节建模

**问题**：母题和风格覆盖了"怎么写"和"什么算好"。下一个盲区是"发生了什么"——情节的结构和逻辑。

**当前基础**：story.yaml 已建模 14 章的人物、场景描述和时间线。

**待验证**：
- [ ] 情节推理引擎 — 知识图谱 + 规则引擎验证情节一致性（人物关系时间演化、因果关系）
- [ ] 跨场景情节连贯性检测 — 同一人物在不同场景的行为是否一致
- [ ] 情节-母题-风格三层联动 — 情节转折点是否由母题承载（如"递毛巾"同时是情节转折和母题体现）

### 路线 2：内容层扩展

**问题**：当前素材和实验仅覆盖都市言情一部小说。需要验证模型在其他类型/媒介上的泛化能力。

**当前基础**：assets 已引入 brochure/history/vision 素材目录。命名约定：`story` 保留为情节建模的关键信息变量，"品牌故事"类内容放在 `history`（工作历史）中。小说作为虚构世界和现实世界的**中转站**——它既有虚构的自由度又有半自传的真实性，是连接两者的桥梁。

**待验证**：
- [ ] 都市言情 style/motif/story 模型 → 校园言情的跨系列转移
- [ ] fiction → brochure（宣传册）的风格迁移 — 事实度高但叙事需求类似
- [ ] vision → history → fiction 的事实度递减管线验证

### 路线 3：CLI 产品化

**问题**：narrative-cli 已是可用工具，但缺少 pairwise 评估、批量处理和 pipeline 串联。

**当前基础**：v0.1 完成 extract/review/inspire。

**待实现**（见 ROADMAP.md）：
- [ ] v0.2 — `inspire --compare` pairwise 排序、集成测试
- [ ] v0.3 — 异步 LLM、批量处理、跨系列转移
- [ ] v1.0 — pipeline 串联、多模型支持

### 路线 4：契约层设计

**问题**：期刊提出了"契约-内容分层"。当前 style/motif/story YAML 是契约层的候选——它们定义规则和约束，内容层（LLM 生成）在规则内运行。

**待明确**：
- [ ] 契约层的完整 DSL — style.yaml + motif.yaml + story.yaml 是否构成最小契约集？还缺什么？
- [ ] 契约的版本管理 — gallery 的 break change 管理策略（期刊提到"关系变化时升级版本"）
- [ ] 契约与 harness 的关系 — 契约定义规则，harness 定义验证方式
